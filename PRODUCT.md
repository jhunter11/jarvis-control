# Jarvis Control

Jarvis is a private operator system for one owner. It manages personal commitments, an AI automation agency, client scopes, and bounded agents.
It supports delegation, review, and memory through a web interface.

## Primary user and platform

The owner works mainly from a desktop and wants conversational commands, with Telegram mobile steering planned.
The interface must show pending decisions, active work, agent authority and memory, and available approval or stop actions.
Local loopback is the trusted V1 surface. Remote access and provider connections require separate security gates.

## Jobs

1. Ask Jarvis for an answer and open its evidence.

2. See the calendar for today, focus, reviews, and approval queue.

3. Traverse human, personal/agency, company/client/project, and agent containment.

4. Inspect delegation, grants, memory sleeves, runs, artifacts, elapsed time, token usage, and known-cost coverage.

5. Build reviewed pages and reusable agent blueprints without executable UI or agents that authorize themselves.

## Trust requirements

- Keep personal, agency, and client memory separate unless an explicit sharing policy permits access.

- Containment grants no authority. Define tool and sleeve access through explicit edges.

- Require approval for external or irreversible actions.

- Show evidence and structured traces. Keep hidden reasoning private.

- Label unknown cost, stale data, unavailable sources, and planned capabilities.
